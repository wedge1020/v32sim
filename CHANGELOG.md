## 20261124-dev
- **Closures in dumps** (v32lua request 1): a function-tagged value with bit 21 set (`(w & 0xFFE00000) == 0x7FA00000`) is shown as a closure, with its RAM record `[code, nupvals, cell_ptr...]` at `(w & 0x1FFFFF) << 1`: v32orun `CANON NAME closure 0xREC code=0x.. nupvals=N` (ROM functions still `CANON NAME function`), `closure@0xREC(code=.. nupvals=N)` in `-d` / `-D` / `-m`; v32sim `x/B` and `locals` print `closure: 0x.. (code 0x.., N upvalues)`.
- **`--heap[=PROG.asm]`** (v32sim) and **`--heap`** (v32orun, with `-a`), request 2: `HEAP F<frame> ptr= used= peak=` at every frame end (`used` = HEAP_POINTER - HEAP_START), with `--gc arena` also `floor= pin= depth= stack=`; `HEAP PEAK` and `HEAP END` at exit. The peak is read after every instruction. Read-only: RAM dumps and exit statuses are the same with and without it (`src/heapwatch.c`).
- **`--heap`: one format in both runners, and free-list accounting.** v32sim and v32orun print exactly `HEAP F<n> ptr=0x%08X used=N peak=N[ free=N blocks=N][ floor=0x%08X pin=0x%08X depth=N stack=0x%08X,0x%08X|-]`, `HEAP PEAK used=N ptr=0x%08X frame=F` and `HEAP END ptr=0x%08X used=N peak=N[ free=N blocks=N] frame=F[ arena fields]` (no `words` token, `stack=-` when no arena is open, 8-digit stack entries; without `HEAP_START` both warn once on stderr and print `ptr` only, v32orun no longer refuses). Frame numbers differ: v32sim counts console frames from power-on, BIOS frames included; v32orun's bare mode counts from 0. With a `v32lua` that frees outgrown blocks (`FREE_MASK`, `FREE_BINS` in the `.asm`: 22 size-class lists, a block's word 0 is the next block and word 1 its size) every frame line and the END line add `free=` (words on the lists) and `blocks=`; `used` is the heap top and counts them, so `used - free` is live memory. The walk is read-only and guarded (step cap, address and size checks): `free=? blocks=?` when a list is corrupt; no fields without the symbols. New test cart `tests/examples/heap_free.lua`. **v32orun `-q` no longer hides the `HEAP F` lines** (it only silences the overrun lines, as documented, and as v32sim does).
- **Fix: `--expect-reach` with `v32as -g` carts** (`__oom_handler`, `__function_game_loop`: "is not a known label"). v32as's `.vbin.debug` names only the functions (`game_loop`), not the runtime's labels or the `__function_` prefix; v32sim now also takes the `F` lines of `NAME.vbin.sym` as code labels (`src/symbols.c`) and `__function_NAME` finds `NAME`; v32orun does the same. `tests/run_heap_tests.sh` now passes with v32as (and the stock `assemble`).
- **`--expect-reach LABEL[,LABEL...]`** (v32sim and v32orun), request 3: `EXPECT REACHED <label> frame=N ip=0x..` and exit 0, or `EXPECT MISSED <labels>` and exit 1; checked before v32orun's `-t` traps. v32orun reads the labels from `PROG.vbin.debug` or `--debug FILE` (`src/expectreach.c`, `sym_lookup_code()`).
- New suite `tests/run_heap_tests.sh` (69 checks, needs v32lua; also in `tools/v32sim-check.sh`); `tests/run_cli_tests.sh` now has 144 checks.
